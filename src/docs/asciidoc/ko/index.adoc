== 1. 소개 (Introduction)
`hg4j`는 **Mercurial (hg) SCM** 버전 관리 시스템을 순수 자바(pure Java) 환경에서 지원하도록 설계된 제품급 라이브러리입니다. Git 진영의 **JGit**이 지닌 정교한 디커플링(Decoupled) 컴포넌트 설계를 벤치마킹하여 개발되었으며, 공식 Mercurial CLI(v7.2.2)와의 완벽한 양방향 바이너리 호환성과 강력한 트랜잭션 무결성을 제공합니다.

본 매뉴얼은 라이브러리의 핵심 아키텍처 레이아웃, 스토리지 구조, 포셀린 파사드 커맨드, 그리고 다국어 지원에 대한 기술적 명세를 다룹니다.

== 2. 핵심 아키텍처 (Core Architecture)
`hg4j`는 저수준 데이터 저장소를 직접 핸들링하는 **Plumbing API**와 고수준 사용자 워크플로우를 제공하는 **Porcelain API**가 엄격하게 이격되어 조율됩니다.

=== 2.1 Plumbing API (내부 배관 구조)
* **`HgRepository`**: `.hg/` 디렉터리 내의 물리 데이터 레이아웃을 총괄하며, 쓰기 잠금 및 트랜잭션 안전성 복구를 지휘하는 허브 클래스.
* **`Dirstate`**: 작업 디렉터리의 파일 추적 상태 관리. 고성능 V2 규격(`DirstateV2Node`)을 지원하여 zero-copy 바이너리 매핑 구조를 제공합니다.
* **`Revlog` (v1)**: 인덱스(`.i`) 및 데이터(`.d`) 파일의 구조를 디스크로부터 직접 로드 및 파싱하고, 메모리 내에서 델타 연쇄를 순차 복원하는 코어 엔진.
* **`TreeWalk` & `RevWalk`**: 매니페스트 파일 트리와 커밋 리비전 그래프의 변경 지점을 탐색하기 위한 대용량 순회 엔진.

=== 2.2 Porcelain API (고수준 파사드)
개발자가 손쉽게 버전 관리 기능을 조작할 수 있도록 `Hg` 클래스의 빌더 파사드로 제공됩니다.

[source,java]
----
// 저장소 초기화
HgRepository repo = Hg.init().setDirectory(new File("/path/to/repo")).call();

// 파일 추적 추가
Hg.add(repo).addFile(new File(repo.getDirectory(), "README.md")).call();

// 변경사항 커밋
Hg.commit(repo).setMessage("첫 번째 커밋!").call();
----

== 3. 상호운용성 및 무결성 (Interoperability & Durability)
`hg4j`는 네이티브 Mercurial과의 양방향 바이너리 상호운용성을 극대화하기 위해 다음과 같은 고급 설계가 장착되어 있습니다:

* **크래시 복구(Journaling)**: 데이터 쓰기 도중 에러 유발 시, `journal`과 `backup`을 통해 데이터를 원자적(Atomic)으로 원상 복구합니다.
* **물리적 잠금**: Java `FileLock`을 활용하여 멀티프로세스 동시 수정 충돌을 철저히 막아줍니다.
* **스토리지 최적화**: 최적의 Myers-diff 및 LCS(최장 공통 부분 수열) 알고리즘을 이식하여 Multi-hunk 델타 생성 성능을 극대화했습니다.

== 4. 문서 빌드 방법 (Building Documentations)
Gradle의 Asciidoctor 플러그인을 사용하여 이 기술 가이드를 정적 HTML 사이트로 빌드하려면 다음 명령을 사용합니다:

[source,bash]
----
./gradlew asciidoctor
----

빌드가 완료되면 `build/docs/asciidoc/ko/index.html` 경로에 국문 전용 HTML 가이드북이 생성됩니다.
