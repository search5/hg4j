== 소개 (Introduction)

`hg4j`는 Mercurial(hg) 버전 관리 시스템을 순수 자바로 구현한 라이브러리입니다. JGit의 구조를
본떠 저수준 **Plumbing** 계층(`HgRepository`, `Revlog`, `Dirstate` 등)과 고수준 **Porcelain**
계층으로 나뉘며, Porcelain 계층은 `hg`의 각 서브커맨드에 대응하는 `Hg` 파사드와 `XxxCommand`
클래스로 이루어집니다.

이 매뉴얼은 **작업 중심의 사용법 가이드**입니다. "파일을 추가하고 커밋한 뒤 원격에 푸시하려면
어떻게 하는가"를 다루지, 모든 클래스와 메서드를 빠짐없이 나열하지는 않습니다. public
클래스와 메서드, 파라미터의 완전한 레퍼런스가 필요하면 Javadoc을 참고하세요.

* **배포판(항상 Maven Central의 최신 릴리스와 일치):** https://javadoc.io/doc/io.github.search5.hg4j/hg4j[javadoc.io/doc/io.github.search5.hg4j/hg4j]
* **로컬 빌드:**
+
[source,bash]
----
./gradlew javadoc    # 영문, build/docs/javadoc/ 아래 생성
./gradlew javadocKo  # 국문, build/docs/javadoc-ko/ 아래 생성
----

이 매뉴얼의 예제 코드는 전부 빌드 시점에 실제로 컴파일됩니다(`src/docs/examples/java` 참고).
`Hg` API가 바뀌어 예제가 깨지면 매뉴얼이 조용히 낡아가는 대신 빌드가 먼저 실패합니다.

=== `Hg` 파사드

이 매뉴얼에서 다루는 작업은 거의 전부 단일 진입점인 `Hg` 클래스를 거칩니다.

* `Hg.init()` / `Hg.cloneRepository()` -- **정적(static)** 메서드입니다. 아직 없는 저장소를
  새로 만들어 `HgRepository`를 반환하는 일이라, 메서드를 불러줄 기존 `Hg` 인스턴스 자체가
  존재하지 않기 때문입니다.
* `Hg.open(path)` / `Hg.wrap(repository)` -- **이미 존재하는** 저장소에 바인딩된 `Hg`
  인스턴스를 얻습니다. 나머지 커맨드(`add()`, `commit()`, `status()`, `push()` 등)는 모두 이
  `Hg` 객체의 **인스턴스** 메서드입니다.
* `Hg`는 `AutoCloseable`을 구현하므로 항상 try-with-resources 블록 안에서 쓰세요.

`Hg` 인스턴스 메서드가 반환하는 `XxxCommand`는 모두 같은 빌더 형태를 따릅니다. `setXxx(...)`로
필요한 값을 설정하고(각 setter는 체이닝할 수 있도록 `this`를 반환합니다), 마지막에 `call()`을
호출해 실제로 실행합니다.
