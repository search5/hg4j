== 브랜치, 북마크, 머지 & 리베이스

=== 네임드 브랜치 vs. 북마크

Mercurial에는 개발 라인에 이름을 붙이는 서로 다른 두 방법이 있고, 동작 방식이 상당히 다릅니다
-- Git에 익숙한 개발자가 흔히 헷갈리는 부분입니다.

* **네임드 브랜치(named branch)**는 커밋 자체에 영구적으로 기록되는 레이블입니다(`branch()`).
  한 번 커밋되면 절대 옮겨가지 않으며, `hg log`에 영원히 남습니다.
* **북마크(bookmark)**(`bookmark()`)는 특정 리비전을 가리키는 이동 가능한 포인터로, 실제로는
  Git의 브랜치에 훨씬 가깝습니다. 활성화된 상태에서 다음 커밋이 생기면 자동으로 앞으로
  이동합니다.

=== 머지하기

[source,java]
----
include::{examplesdir}/MergingExamples.java[tag=merge-branches]
----

충돌이 발생한 머지는 예외가 **아닙니다** -- `merge()`는 정상적으로 반환되고, 충돌 경로는
`MergeResult.isConflicted()`/`getConflicts()`로 확인합니다. 충돌한 각 파일에는 이미 표준
`<<<<<<< / ======= / >>>>>>>` 마커가 디스크에 쓰여 있으므로, 이를 해결한 뒤 다른 머지 커밋과
동일하게 커밋하면 됩니다.
