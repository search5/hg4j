== 소개 (Introduction)

`hg4j`는 Mercurial(hg) 버전 관리 시스템을 순수 자바로 구현한 라이브러리로, JGit의 구조를
본떠 저수준 **Plumbing** 계층(`HgRepository`, `Revlog`, `Dirstate` 등)과 고수준 **Porcelain**
계층 -- `hg`의 각 서브커맨드에 대응하는 `Hg` 파사드와 `XxxCommand` 클래스들 -- 로 나뉩니다.

이 매뉴얼은 **작업 중심의 사용법 가이드**입니다. "파일을 추가하고 커밋한 뒤 원격에 푸시하려면
어떻게 하는가"를 다루지, 모든 클래스와 메서드를 빠짐없이 나열하지는 않습니다. 모든 public
클래스/메서드/파라미터에 대한 완전한 레퍼런스가 필요하면 생성된 Javadoc을 참고하세요.

[source,bash]
----
./gradlew javadoc    # 영문, build/docs/javadoc/ 아래 생성
./gradlew javadocKo  # 국문, build/docs/javadoc-ko/ 아래 생성
----

이 매뉴얼의 모든 예제 코드는 빌드 시점에 실제로 컴파일됩니다(`src/docs/examples/java` 참고).
`Hg` API가 바뀌어 예제가 깨지는 경우, 매뉴얼이 조용히 낡아버리는 대신 빌드 자체가 실패합니다.

=== `Hg` 파사드

이 매뉴얼의 거의 모든 내용은 단일 진입점인 `Hg` 클래스를 거쳐 갑니다.

* `Hg.init()` / `Hg.cloneRepository()` -- **정적(static)** 메서드입니다. 아직 존재하지 않는
  저장소를 새로 만들고 결과로 `HgRepository`를 반환하므로, 호출할 기존 `Hg` 인스턴스가 없기
  때문입니다.
* `Hg.open(path)` / `Hg.wrap(repository)` -- **이미 존재하는** 저장소에 바인딩된 `Hg`
  인스턴스를 얻습니다. 그 외 모든 커맨드(`add()`, `commit()`, `status()`, `push()` 등)는 이
  `Hg` 객체의 **인스턴스** 메서드입니다.
* `Hg`는 `AutoCloseable`을 구현합니다 -- 항상 try-with-resources 블록 안에서 사용하세요.

`Hg` 인스턴스 메서드가 반환하는 각 `XxxCommand`는 동일한 빌더 형태를 따릅니다: `setXxx(...)`
호출로 설정한 뒤(각 호출은 체이닝을 위해 `this`를 반환), `call()`을 호출해 실제로 실행합니다.
