=== Init

새 저장소를 만듭니다(`hg init`). `.hg/requires`를 쓰고 `.hg/store`와 구버전 호환용 `.hg/00changelog.i` 파일을 만든 뒤 `HgRepository`를 반환합니다. 기본 요구 사항 `dotencode`, `fncache`, `generaldelta`, `revlogv1`, `store`는 항상 기록되며 아래 설정자는 여기에 더합니다. 모든 설정자의 기본값은 `false`입니다.

[cols="2,5"]
|===
|메서드 |의미

|`setDirectory(File)`
|저장소를 만들 디렉터리입니다(`.hg`는 그 안에 만듭니다). 없으면 상위 디렉터리까지 만듭니다. 기본값이 없으며 지정하지 않으면 `call()`이 실패합니다.

|`setDirstateV2(boolean)`
|`dirstate-v2` 요구 사항을 추가합니다.

|`setUseZstd(boolean)`
|`revlog-compression-zstd` 요구 사항을 추가합니다.

|`setChangelogV2(boolean)`
|`format.exp-use-changelog-v2`입니다. `exp-changelog-v2`를 추가합니다(체인지로그가 docket 기반 revlog v2 형식을 씁니다).

|`setSidedataCopies(boolean)`
|`format.exp-use-copies-side-data-changeset`입니다. `exp-copies-sidedata-changeset`을 추가하며(커밋이 `SD_FILES` sidedata 레코드를 가집니다) `setChangelogV2`를 함께 적용합니다.

|`setTreemanifest(boolean)`
|`experimental.treemanifest`입니다. `treemanifest`를 추가합니다(매니페스트가 디렉터리별로 재귀 분할됩니다).

|`setPersistentNodemap(boolean)`
|`format.use-persistent-nodemap`입니다. `persistent-nodemap`을 추가합니다(`<radix>.n` nodemap 트라이를 유지합니다).

|`setFileIndexV1(boolean)`
|`format.use-fileindex-v1`입니다. `fileindex-v1`을 추가하고(기수 트라이 파일 인덱스가 fncache 기반 저장소 배치를 대체합니다) `fncache`/`dotencode`를 뺍니다. `setPersistentNodemap`을 함께 적용합니다.

|`setGeneralV2(boolean)`
|`experimental.revlogv2`입니다. `exp-revlogv2.2`를 추가하고(매니페스트와 파일로그가 일반 revlog v2 형식을 씁니다) `revlogv1`을 뺍니다. `setFileIndexV1`과 `setPersistentNodemap`을 함께 적용합니다.
|===

실행: `HgRepository call() throws IOException`. 디렉터리를 지정하지 않으면 `IllegalStateException`을 던집니다. 디렉터리를 만들 수 없거나 경로가 디렉터리가 아니거나 `.hg/requires` 또는 `.hg/00changelog.i`를 쓸 수 없으면 `HgRepositoryNotFoundException`을 던집니다. `treemanifest`를 `fileindex-v1` 또는 `general-v2`와 함께 쓰면 `HgValidationException`을 던집니다.

잠금과 dirstate: 잠금을 잡지 않으며 `changing_files`/`changing_parents` 컨텍스트도 쓰지 않습니다.

hg 원본과 다른 점: 항상 단일 파일, 비 `share-safe` 형태의 `.hg/requires`를 씁니다(`.hg/store/requires` 분리 없음). javadoc에 따르면 실제 hg도 이 형태를 받아들입니다. 요구 사항 간 함의 규칙과 treemanifest 중단 메시지는 실제 hg를 따릅니다.

[source,java]
----
HgRepository repo = new InitCommand()
        .setDirectory(new File("/work/proj"))
        .setDirstateV2(true)
        .call();
----

=== Add

파일 추적을 시작합니다(`hg add`).

[cols="2,5"]
|===
|메서드 |의미

|`addFile(String)`
|존재하는 파일이나 심볼릭 링크의 저장소 기준 경로 하나를 대기열에 넣습니다(역슬래시는 `/`로 바꾸며 `null`이나 빈 문자열은 무시합니다). `addFile` 경로가 하나라도 있으면 `call()`은 정확히 그 경로만 추가하고 패턴 선택은 쓰지 않습니다.

|`setPatterns(String...)`
|`hg add [FILE]...`입니다. 패턴(`kind:pattern`, `set:EXPRESSION`)을 받습니다.

|`setInclude(String...)`
|`hg add -I`입니다.

|`setExclude(String...)`
|`hg add -X`입니다.

|`setCwd(String)`
|저장소 루트 기준 현재 디렉터리이며 상대 패턴을 읽는 기준입니다.

|`setSubrepos(boolean)`
|`hg add -S`입니다. hg 서브저장소의 unknown 파일도 추가합니다. 없으면 정확히 이름을 지정한 파일만 서브저장소에 닿습니다.

|`getSubrepoMessages()`
|서브저장소에 관한 메시지입니다(예: `skipping missing subrepository`).
|===

실행: `void call() throws IOException, HgLockException`. 명시 경로가 없거나 일반 파일도 심볼릭 링크도 아니면 `HgValidationException`을 던집니다(끊어진 심볼릭 링크는 받아들입니다). `addFile` 경로도 선택 조건도 없으면 `scanWorkingCopy()`의 모든 추적되지 않는 파일을 추가합니다. 선택 조건이 있으면 일치하는 unknown 파일, 디스크에 다시 나타난 removed 파일, 정확히 이름을 지정한 ignored 파일만 추가합니다.

잠금과 dirstate: `lockWorkingCopy()`를 잡은 뒤 파일 추가와 서브저장소 처리를 `changingFiles(...)`로 감쌉니다. 각 서브저장소는 부모의 잠금을 쥔 채 자신의 작업 사본 잠금으로 추가를 수행합니다.

hg 원본과 다른 점: `commands.add`를 따른다는 것 외에 소스에 명시된 차이는 없습니다. 이미 dirstate 항목이 있고 상태가 `a`가 아닌 경로는 실제 hg의 normallookup처럼 모호한 stat의 상태 `n`으로 복원하며, 이미 상태 `a`인 항목은 그대로 둡니다.

[source,java]
----
new AddCommand(repo)
        .setPatterns("src/**.java")
        .setExclude("glob:**/Test*.java")
        .call();
----

=== Addremove

추적되지 않는 파일을 모두 추가하고 사라진 추적 파일을 모두 removed로 표시합니다(`hg addremove`).

[cols="2,5"]
|===
|메서드 |의미

|`setSubrepos(boolean)`
|`hg addremove -S`입니다. hg 서브저장소에서도 추가와 제거를 수행합니다. 서브저장소는 항상 자신의 서브저장소로도 재귀합니다.

|`getMessages()`
|마지막 호출이 변경 파일 외에 알린 내용입니다(예: `skipping missing subrepository`).
|===

실행: `List<String> call() throws IOException, HgLockException`. `A path/new.txt`, `R path/gone.txt` 같은 status 형식의 줄을 반환합니다.

잠금과 dirstate: 저장소 상태를 읽기 전에 `resolvePushLockTimeoutMs()`의 제한 시간으로 `lockWorkingCopy(timeout)`을 잡습니다. 서브저장소 옵션이 켜져 있으면 서브저장소를 먼저 처리하며 각각 자신의 잠금을 씁니다. 추가와 제거는 `AddCommand.call()`과 `RemoveCommand.call()`(force)에 위임하며, 이들은 같은 잠금을 다시 잡고 자신의 `changing_files` 컨텍스트를 씁니다. `AddremoveCommand` 자체는 `changing_files`를 열지 않습니다.

hg 원본과 다른 점: 소스에는 패턴, include, exclude, 유사도, dry-run 옵션이 없습니다.

[source,java]
----
List<String> changes = new AddremoveCommand(repo).call();
----

=== Remove

파일 추적을 해제하고 작업 디렉터리에서 삭제합니다(`hg remove`).

[cols="2,5"]
|===
|메서드 |의미

|`setFile(String)`
|`call()`이 쓰는 단일 경로입니다.

|`setForce(boolean)`
|커밋되지 않은 변경이 있는(added 또는 modified) 파일도 `hg remove -f`처럼 제거합니다. 기본값은 false이며 이 경우 거부합니다.

|`setPatterns(String...)`
|`callSelected()`용 패턴입니다.

|`setInclude(String...)`
|`-I`입니다. 이 패턴과 일치하는 파일만 대상으로 합니다(기본은 glob).

|`setExclude(String...)`
|`-X`입니다. 이 패턴과 일치하는 파일은 제외합니다(기본은 glob).

|`setCwd(String)`
|저장소 루트 기준 현재 디렉터리이며 상대 패턴을 읽는 기준입니다.

|`setSubrepos(boolean)`
|`-S`입니다. 패턴이 닿는 모든 hg 서브저장소에서도 제거합니다. 없으면 이름이 지정된 서브저장소만 들어갑니다.

|`getWarnings()`
|마지막 `callSelected()`가 하지 못한 일을 Mercurial의 표현으로 돌려줍니다.
|===

실행:

* `boolean call() throws IOException, HgLockException`: 파일 하나를 제거하며 제거했으면 `true`를 반환합니다. 파일이 없으면 `IllegalStateException`, 추적되지 않거나(force 없이) added 또는 modified이면 `HgValidationException`을 던집니다.
* `List<String> callSelected() throws IOException, HgLockException`: 패턴이 고른 추적 파일을 제거하고 제거된 경로를 반환합니다. 패턴이 없으면 `HgValidationException("no files specified")`을 던집니다. 안전하게 제거할 수 없는 파일(added 표시, modified)은 force가 아니면 그대로 두고 `getWarnings()`에 남기며 나머지는 제거합니다.

잠금과 dirstate: 두 메서드 모두 `lockWorkingCopy()` 다음에 `changingFiles(...)`를 씁니다. 서브저장소는 자신의 작업 사본 잠금을 잡습니다. 상태 `a`인 파일을 force로 제거하면 추적만 해제하고 디스크에는 남기며, 그 외 파일은 디스크에서 삭제하고 `r`로 표시합니다.

hg 원본과 다른 점: 위 내용 외에 명시된 것은 없습니다.

[source,java]
----
new RemoveCommand(repo)
        .setPatterns("old/*.txt")
        .callSelected();
----

=== Forget

작업 사본은 건드리지 않고 추적만 중단합니다(`hg forget`).

[cols="2,5"]
|===
|메서드 |의미

|`setFile(String)`
|`call()`이 쓰는 단일 경로입니다.

|`setPatterns(String...)`
|`callSelected()`용 패턴입니다.

|`setInclude(String...)`
|`-I`입니다.

|`setExclude(String...)`
|`-X`입니다.

|`setCwd(String)`
|저장소 루트 기준 현재 디렉터리입니다.

|`getWarnings()`
|마지막 `callSelected()`가 하지 못한 일입니다.
|===

실행:

* `void call() throws IOException, HgLockException`: 파일 하나를 잊습니다(`setFile`은 필수입니다). 추가만 된 파일은 dirstate에서 제거하고 커밋된 파일은 다음 커밋에서 제거되도록 표시하며, 디스크의 파일은 건드리지 않습니다. 파일이 없으면 `IllegalStateException`, 추적되지 않으면 `HgValidationException("File is not tracked: ...")`을 던집니다.
* `List<String> callSelected() throws IOException, HgLockException`: 선택된 파일을 잊고 그 목록을 반환합니다. 패턴이 없으면 `HgValidationException("no files specified")`을 던집니다. 상태 `a`인 파일은 unknown이 되고, 커밋된 파일은 `r`로 표시됩니다.

잠금과 dirstate: `lockWorkingCopy()` 다음에 `changingFiles(...)`를 씁니다. 서브저장소는 부모의 matcher가 그 안에서 지정한 파일만 각자의 잠금으로 잊으며, 서브저장소가 잊은 파일은 서브저장소 경로를 앞에 붙여 보고하고, 디스크에 없는 서브저장소는 경고와 함께 건너뜁니다.

hg 원본과 다른 점: 명시된 것은 없습니다.

[source,java]
----
List<String> gone = new ForgetCommand(repo)
        .setPatterns("build/**")
        .callSelected();
----

=== Copy

추적 중인 파일을 복사하고 복사 원본을 기록합니다(`hg copy`).

[cols="2,5"]
|===
|메서드 |의미

|`setSource(String)`
|`call()`의 추적 중인 원본 저장소 기준 경로입니다. `call()`에서 필수입니다.

|`setDestination(String)`
|`call()`의 대상 저장소 기준 경로입니다. `call()`에서 필수입니다.

|`setForce(boolean)`
|기존 대상을 덮어씁니다(`--force`). 기본값은 false입니다.

|`setPatterns(String...)`
|`callPatterns()`용 `SOURCE... DEST`이며 명령줄과 같습니다. 각 항목은 패턴(`kind:pattern`, 일반 이름은 `setCwd` 기준 상대 경로)이고, 원본이 여러 개이면 대상은 기존 디렉터리여야 합니다.

|`setAfter(boolean)`
|`--after`입니다. 디스크에서 이미 일어난 복사를 기록합니다.

|`setDryRun(boolean)`
|`--dry-run`입니다. 하게 될 일을 보고만 합니다.

|`setForget(boolean)`
|`--forget`입니다. 대상의 복사 표시를 해제하고 파일은 남깁니다.

|`setAtRev(String)`
|`--at-rev REV`입니다. 변경셋 REV에 복사를 기록하며(forget과 함께면 제거) REV는 변경된 사본으로 교체됩니다. `setAfter` 또는 `setForget`이 필요하고 REV는 자식 없는 draft여야 합니다.

|`setInclude(String...)`
|`-I`입니다.

|`setExclude(String...)`
|`-X`입니다.

|`setCwd(String)`
|저장소 루트 기준 현재 디렉터리입니다.
|===

실행:

* `void call() throws IOException, HgLockException`: 단일 복사입니다. 원본을 대상으로 복사하고 대상을 added로 표시하며, 실제 hg가 그럴 때 복사 원본을 기록합니다. 원본은 그대로 둡니다. 원본과 대상이 없으면 `IllegalStateException`, 디스크에 원본이 없으면 `HgRepositoryNotFoundException`, force 없이 대상이 존재하거나 원본이 추적되지 않으면(또는 상태 `r`이면) `HgValidationException`을 던집니다. 생성자는 `null` 저장소에 `IllegalArgumentException`을 던집니다.
* `PatternResult callPatterns() throws IOException, HgLockException`: `record PatternResult(boolean failed, List<String> warnings, List<String> status)`를 반환합니다. 위의 모든 옵션을 받습니다. 실제 hg처럼 처리할 수 없는 파일은 경고하고 계속하며, `warnings`와 `status`는 실제 hg가 출력하는 줄이고 `failed()`는 파일을 처리하지 못했을 때 true입니다(종료 코드 1).

잠금과 dirstate: `call()`은 `lockWorkingCopy()` 다음에 `changingFiles(...)`를 쓰며, dirstate는 컨텍스트가 끝날 때 한 번 쓰고 실패하면 쓰지 않습니다. `callPatterns()`는 `CopyEngine`을 통해 `lockWorkingCopy()` 다음에 `changingFiles(...)`를 쓰고, dry run이 아니면 dirstate를 씁니다. `atRev`를 쓰면 작업 사본 잠금은 잡지만 dirstate changing 컨텍스트는 열지 않습니다.

hg 원본과 다른 점: 클래스 javadoc이 확인된 동작을 적고 있습니다. 복사 체인은 직전 원본이 커밋되지 않은 추가(상태 `a`)인 동안에만 앞선 원본으로 접히고, 한 번도 복사본이 아닌 새로 add한 파일을 복사하면 복사 메타데이터를 저장하지 않으며, 심볼릭 링크는 링크 자체로 복사합니다.

[source,java]
----
new CopyCommand(repo)
        .setSource("a.txt")
        .setDestination("b.txt")
        .call();
----

=== Rename

파일을 옮기고 이름 변경을 기록합니다(`hg rename`, `hg mv`).

[cols="2,5"]
|===
|메서드 |의미

|`setSource(String)`
|`call()`의 원본 저장소 기준 경로이며 존재하는 파일이나 심볼릭 링크입니다(끊어진 심볼릭 링크도 허용). `call()`에서 필수입니다.

|`setTarget(String)`
|`call()`의 대상 저장소 기준 경로입니다. `call()`에서 필수입니다.

|`setPatterns(String...)`
|`callPatterns()`용 `SOURCE... DEST`이며 명령줄과 같습니다. 각 항목은 패턴(`kind:pattern`, 일반 이름은 `setCwd` 기준 상대 경로)이고, 원본이 여러 개이면 대상은 기존 디렉터리여야 합니다.

|`setForce(boolean)`
|`-f`/`--force`입니다. 기존 대상을 덮어씁니다(`callPatterns()`에서만 적용).

|`setAfter(boolean)`
|`--after`입니다. 디스크에서 이미 일어난 이름 변경을 기록합니다.

|`setDryRun(boolean)`
|`--dry-run`입니다. 하게 될 일을 보고만 합니다.

|`setForget(boolean)`
|`--forget`입니다. 대상의 복사 표시를 해제하고 파일은 남깁니다.

|`setAtRev(String)`
|`--at-rev REV`입니다. 변경셋 REV에 이름 변경을 기록하며(`setForget`과 함께면 제거) REV는 변경된 사본으로 교체됩니다. `setAfter` 또는 `setForget`이 필요하고 REV는 자식 없는 draft여야 합니다.

|`setInclude(String...)`
|`-I`입니다.

|`setExclude(String...)`
|`-X`입니다.

|`setCwd(String)`
|저장소 루트 기준 현재 디렉터리입니다.
|===

실행:

* `void call() throws IOException, HgLockException`: 단일 이름 변경입니다. 원본과 대상이 없으면 `IllegalStateException`, 원본이 존재하지 않으면 `HgRepositoryNotFoundException`을 던집니다. 파일을 옮기고(기존 대상은 교체하고 상위 디렉터리를 만듭니다) 원본을 `r`, 대상을 `a`로 표시하며 복사를 기록합니다. dirstate는 끝에서 한 번만 쓰고, 어느 단계든 실패하면 쓰지 않습니다(옮긴 파일은 되돌리지 않습니다).
* `PatternResult callPatterns() throws IOException, HgLockException`: 모든 옵션을 받는 `hg rename [OPTION]... SOURCE... DEST`입니다. `CopyCommand`와 같은 `PatternResult` record를 반환합니다(실제 hg는 처리할 수 없는 파일을 경고하고 계속하며 `failed()`가 이를 알려 줍니다).

잠금과 dirstate: `CopyCommand`와 같습니다. `call()`과 `callPatterns()`는 모두 `CopyEngine`을 실행하며, 엔진이 `lockWorkingCopy()` 다음에 `changingFiles(...)`를 씁니다.

hg 원본과 다른 점: `call()`은 없습니다. `callPatterns()`와 같은 엔진을 실행하며 `hg rename`이 거부하는 경우를 똑같이 거부합니다(hg 7.2로 확인). 추적되지 않는 원본(`not copying - file is not managed`), 삭제 예정인 원본(`not copying - file has been marked for remove`), `setForce(true)` 없이 이미 있는 대상(`not overwriting - file exists`)은 각각 경고와 `no files to copy`를 담은 `HgValidationException`으로 거부합니다. 추가만 하고 커밋하지 않은 원본은 복사 기록 없이 이동하며, 이름을 바꾼 파일을 다시 바꾸면 처음 원본이 복사 원본으로 남습니다. 2026-11 이전의 `call()`은 이 검사를 건너뛰고 기존 대상을 조용히 덮어썼습니다.

[source,java]
----
new RenameCommand(repo)
        .setSource("old.txt")
        .setTarget("new.txt")
        .call();
----

=== Revert

파일을 특정 리비전의 내용으로 되돌립니다(`hg revert`). 기본 대상은 첫 번째 부모입니다.

[cols="2,5"]
|===
|메서드 |의미

|`setFile(String)`
|`call()`의 단일 경로입니다.

|`setRevision(String)`
|되돌릴 대상 리비전입니다(`-r`). 체인지로그를 기준으로 해석합니다. `null`이나 빈 값(기본값)이면 작업 디렉터리의 첫 번째 부모입니다.

|`setPatterns(String...)`
|`callSelected()`용 패턴입니다(`kind:pattern`, `set:EXPRESSION`이며 일반 이름은 현재 디렉터리 기준).

|`setInclude(String...)`
|`-I`입니다. 이 패턴과 일치하는 파일만 대상으로 합니다(기본은 glob).

|`setExclude(String...)`
|`-X`입니다. 이 패턴과 일치하는 파일은 제외합니다(기본은 glob).

|`setCwd(String)`
|저장소 루트 기준 현재 디렉터리이며 상대 패턴을 읽는 기준입니다.

|`setAll(boolean)`
|`--all`입니다. 변경된 모든 파일을 대상으로 합니다.

|`getWarnings()`
|마지막 `callSelected()`가 하지 못한 일입니다.

|`getSubrepoMessages()`
|서브저장소 메시지입니다(`reverting subrepo NAME`).
|===

실행:

* `boolean call() throws IOException, HgLockException`: 파일 하나를 대상 리비전의 상태로 되돌리며 되돌렸으면 `true`를 반환합니다. 파일이 없으면 `IllegalStateException`, 저장소에 부모 커밋이 없고 파일이 added가 아니면 `HgValidationException`을 던집니다.
* `List<String> callSelected() throws IOException, HgLockException`: 일치하는 modified, added, removed, deleted 파일을 되돌리고 되돌린 경로를 정렬해 반환합니다. `getWarnings()`와 `getSubrepoMessages()`는 호출마다 처음에 초기화됩니다. 파일, 패턴, `setAll`이 모두 없으면(힌트 포함), 리비전 없이 커밋되지 않은 병합 상태이면, 또는 일치하는 서브저장소가 대상 리비전에 없으면 `HgValidationException`을, 리비전을 해석할 수 없으면 `HgRevisionNotFoundException`을 던집니다.

잠금과 dirstate: `call()`은 `lockWorkingCopy()` 다음에 `changingFiles(...)`를 씁니다. `callSelected()`는 잠금 전에 부모를 읽고 리비전을 해석한 뒤, status 읽기와 파일별 `call()` 호출 동안 `lockWorkingCopy()`를 유지합니다(파일별 호출은 잠금과 자신의 `changingFiles`를 재진입으로 씁니다). 선택에 닿은 서브저장소는 되돌린 뒤 기록된 리비전으로 업데이트합니다.

hg 원본과 다른 점(클래스 javadoc): modified 파일은 덮어쓰기 전에 `<file>.orig`로 백업하고 clean 파일은 백업하지 않습니다. 커밋된 적 없는 added 파일을 되돌리면 추적만 해제하고 디스크에 남깁니다. 대상 리비전에 없는 파일은 삭제하고 `r`로 표시합니다.

[source,java]
----
new RevertCommand(repo)
        .setPatterns("a.txt")
        .setRevision("tip")
        .callSelected();
----

=== Purge

추적되지 않고 무시되지도 않는 파일과 빈 디렉터리를 삭제합니다(`hg purge`, `hg clean`).

[cols="2,5"]
|===
|메서드 |의미

|`setPurgeIgnored(boolean)`
|`--all`입니다. ignored 파일과 그것 때문에 비는 디렉터리도 제거합니다.

|`setPurgeFiles(boolean)`
|`--files`이며 기본값은 켜짐입니다. 끄면 파일은 남고 빈 디렉터리만 제거할 수 있습니다.

|`setPurgeDirectories(boolean)`
|비게 되는 추적되지 않는 디렉터리를 제거합니다. 기본값은 true이며 false이면 남겨 둡니다(`hg purge --files`처럼 범위를 좁힙니다).
|===

실행: `void call() throws IOException`. 저장소 루트 아래에서 dirstate에 없는 모든 항목이 후보입니다. ignored 경로는 `setPurgeIgnored`를 켜지 않으면 남기며, `setPurgeFiles`가 켜져 있으면 파일을 삭제하고 `setPurgeDirectories`가 켜져 있으면 그 뒤 비어 있는 추적되지 않는 디렉터리를 삭제합니다.

잠금과 dirstate: 잠금을 잡지 않습니다. dirstate는 읽기만 하고 쓰지 않으며 `changing_files`/`changing_parents` 컨텍스트도 쓰지 않습니다.

hg 원본과 다른 점(클래스 javadoc): 디렉터리 심볼릭 링크는 불투명한 항목 하나로 취급해 따라 들어가지 않고, 끊어진 심볼릭 링크는 삭제하며, 선언된 서브저장소 경로와 `.hg`에는 들어가지 않습니다. 기본값이 빈 디렉터리 제거인 것은 실제 hg와 같습니다.

[source,java]
----
new PurgeCommand(repo)
        .setPurgeIgnored(true)
        .call();
----

=== Status

작업 디렉터리를 dirstate와 부모 커밋에 비교합니다(`hg status`).

[cols="2,5"]
|===
|메서드 |의미

|`setTreeFilter(HgTreeFilter)`
|검사할 경로를 제한합니다(narrow 지원). `null`은 무시합니다. 기본값 `HgTreeFilter.ALL`은 더 빠른 dirstate 기반 스캔을 씁니다.

|`setPatterns(String...)`
|보고할 파일입니다(패턴, `kind:pattern`, `set:EXPRESSION`).

|`setInclude(String...)`
|`-I`입니다.

|`setExclude(String...)`
|`-X`입니다.

|`setCwd(String)`
|저장소 루트 기준 현재 디렉터리입니다.
|===

실행: `Status call() throws IOException`. 첫 번째 부모를 기준으로 status를 계산하며 패턴, include, exclude에 일치하는 경로만 보고합니다. `null`을 반환하지 않습니다. `Status`에는 `getAdded()`, `getModified()`, `getRemoved()`, `getClean()`, `getUntracked()`가 있으며 모두 `Set<String>`을 반환합니다.

잠금과 dirstate: status 자체는 잠금을 잡지 않습니다. stat을 갱신할 수 있는 항목을 찾으면 `_poststatusfixup`에 따라 `lockWorkingCopy(0)`으로 반영합니다(잠금을 기다리지 않으며, 그 시점에 잠금이 비어 있지 않으면 수정은 버려집니다). `changing_files`/`changing_parents` 컨텍스트는 쓰지 않습니다.

hg 원본과 다른 점: 명시된 것은 없습니다.

[source,java]
----
Status s = new StatusCommand(repo)
        .setPatterns("src")
        .call();
Set<String> modified = s.getModified();
----

=== Diff

두 리비전 사이의 파일별 unified diff를 계산합니다(`hg diff -r OLD -r NEW`). 이 클래스는 작업 디렉터리와는 비교하지 않습니다.

[cols="2,5"]
|===
|메서드 |의미

|`setOldRevision(int)`
|이전 리비전 번호입니다(`hg diff -r OLD:NEW`). 기본값은 새 리비전의 첫 번째 부모이며 -1은 빈 매니페스트와 비교합니다.

|`setOldRevision(NodeId)`
|노드로 지정한 이전 리비전입니다. `null`이면 기본값(새 리비전의 첫 번째 부모)으로 복원하고, 체인지로그에 없는 노드는 빈 매니페스트로 취급합니다.

|`setNewRevision(int)`
|새 리비전 번호입니다. 기본값은 tip이고 -1은 빈 매니페스트와 비교합니다.

|`setNewRevision(NodeId)`
|노드로 지정한 새 리비전입니다. `null`이면 기본값(tip)으로 복원하고, 체인지로그에 없는 노드는 빈 매니페스트로 취급합니다.

|`setTreeFilter(HgTreeFilter)`
|필터가 받아들이는 경로로 diff를 제한하며 패턴 선택과 함께 적용됩니다. `null`은 무시하고 이전 필터(처음에는 모두 허용)를 유지합니다.

|`setPatterns(String...)`
|diff할 파일입니다(`kind:pattern`, `set:EXPRESSION`).

|`setInclude(String...)`
|`-I`입니다.

|`setExclude(String...)`
|`-X`입니다.

|`setCwd(String)`
|저장소 루트 기준 현재 디렉터리입니다.
|===

실행: `List<DiffEntry> call() throws IOException`. 각 `DiffEntry`는 `getPath()`, `getChangeType()`(`ADD`, `MODIFY`, `DELETE`), `getDiffContent()`(unified diff 텍스트)를 가집니다. 트리 필터와 패턴 선택을 통과한 달라진 파일마다 항목 하나를 반환합니다. 별다른 설정이 없으면 tip을 첫 번째 부모와 diff합니다. 저장소에 변경셋이 없으면 빈 리스트를 반환합니다.

잠금과 dirstate: 없습니다. 아무것도 쓰지 않으며 dirstate 컨텍스트도 없습니다. 먼저 `refreshIfChangedOnDisk()`를 호출합니다.

hg 원본과 다른 점: javadoc에 따르면 새 리비전을 명시적으로 -1로 주면 tip이 아니라 빈 매니페스트를 뜻합니다(센티널 `NOT_SET`).

[source,java]
----
List<DiffCommand.DiffEntry> d = new DiffCommand(repo)
        .setOldRevision(1)
        .setNewRevision(2)
        .call();
----

=== Resolve

병합 충돌 상태를 읽고 갱신합니다(`hg resolve`). `MergeCommand`의 짝이며 `.hg/merge/state2`를 다룹니다.

[cols="2,5"]
|===
|메서드 |의미

|`setFile(String)`
|표시할 병합 상태 안의 파일의 저장소 기준 경로입니다. `null`(기본값)이면 아무것도 표시하지 않으며 `markResolved` 또는 `markUnresolved`와 함께일 때만 효과가 있습니다.

|`markResolved(boolean)`
|파일을 resolved로 표시합니다(`hg resolve --mark`). 기본값은 false입니다.

|`markUnresolved(boolean)`
|파일을 unresolved로 표시합니다(`hg resolve --unmark`). 기본값은 false이며 `markResolved`도 true이면 무시합니다.

|`list(boolean)`
|파일 하나를 표시한 경우에도 병합 상태의 모든 파일 상태를 반환합니다(`hg resolve --list`). 기본값은 false입니다. 표시하지 않으면 어느 쪽이든 모든 파일을 반환합니다.
|===

실행: `Map<String, Boolean> call() throws IOException, HgLockException`. 맵은 경로에서 resolved(true) 또는 unresolved(false)로 이어집니다. `list` 없이 표시하면 표시한 파일만 반환합니다. 병합 중이 아닌데 표시하면("resolve command not applicable when not merging") 또는 병합에 속하지 않는 경로이면 `HgValidationException`을 던집니다. 생성자는 `null` 저장소에 `IllegalArgumentException`을 던집니다.

잠금과 dirstate: 병합 상태를 읽기 전에 `resolvePushLockTimeoutMs()`의 제한 시간으로 `lockWorkingCopy(timeout)`을 잡습니다. `changing_files`/`changing_parents` 컨텍스트는 쓰지 않습니다.

hg 원본과 다른 점: 명시된 것은 없습니다. 병합 도구를 다시 실행하는 기능은 이 클래스의 소스에서 확인되지 않습니다.

[source,java]
----
Map<String, Boolean> m = new ResolveCommand(repo)
        .setFile("a.txt")
        .markResolved(true)
        .call();
----

=== Update

리비전을 작업 사본으로 체크아웃합니다(`hg update`).

[cols="2,5"]
|===
|메서드 |의미

|`setRevision(String)`
|대상 리비전이며 `call()` 전에 지정해야 합니다. 리비전 식별자(리비전 번호, 노드 hex 또는 접두사, 심볼릭 이름) 또는 이름 있는 브랜치를 받으며, 브랜치는 그 위에서 번호가 가장 높은 리비전을 고릅니다. 해석할 수 없거나 모호하면 예외를 던집니다.

|`setForce(boolean)`
|커밋되지 않은 변경이 있어도 `hg update -C`처럼 업데이트합니다. 기본값은 false이며 added, modified, removed 파일이 있으면 업데이트가 실패합니다.

|`setTreeFilter(HgTreeFilter)`
|체크아웃할 경로를 제한합니다(narrow 지원). `null`은 무시합니다. 기본값 `ALL`로 두면 저장소의 narrowspec을 씁니다.

|`registerPreUpdateHook(HgHook)`
|업데이트 전에 실행하는 훅입니다(컨텍스트 키 `repository`, `targetRevision`, `force`). false를 반환하면 업데이트가 거부됩니다. `null`은 무시합니다.

|`registerPostUpdateHook(HgHook)`
|업데이트 후에 실행하는 훅입니다(컨텍스트 키 `targetNode`, `repository`). 실패는 로그에 남기고 무시합니다. `null`은 무시합니다.

|`setProgressMonitor(ProgressMonitor)`
|LFS 다운로드 진행과 그에 관해 Mercurial이 출력하는 줄을 받습니다.
|===

실행: `byte[] call() throws IOException, HgLockException`. 현재 체크아웃된 리비전의 20바이트 노드 id를 반환합니다. `HgValidationException`("Working directory has uncommitted changes. Use force to update.", "Repository is empty, cannot update.", "Update rejected by PRE_UPDATE hook"), `HgRevisionNotFoundException`(리비전을 해석할 수 없거나 모호함), `HgRepositoryNotFoundException`(추적 파일의 파일로그 인덱스가 없음)을 던집니다.

잠금과 dirstate: `lockWorkingCopy()` 다음에 업데이트 전체를 `changingParents(...)`로 감쌉니다(정상 종료 시 dirstate를 씁니다). 체크아웃 뒤에는 서브저장소로 재귀하고 활성 북마크를 갱신합니다.

hg 원본과 다른 점: 훅 지원은 hg4j 고유 기능이며, 그 외 명시된 차이는 없습니다.

[source,java]
----
byte[] node = new UpdateCommand(repo)
        .setRevision("default")
        .setForce(false)
        .call();
----

=== Merge

대상 리비전을 작업 사본에 병합하고(`hg merge`) 끝나지 않은 병합을 중단합니다(`hg merge --abort`).

[cols="2,5"]
|===
|메서드 |의미

|`setNodeId(byte[])`
|20바이트 노드 id로 지정한 대상입니다. `setRevision`보다 우선합니다. `null`이면 지웁니다.

|`setNodeId(NodeId)`
|노드 id로 지정한 대상입니다. `setRevision`보다 우선합니다. `null`이면 지웁니다.

|`setRevision(int)`
|체인지로그 리비전 번호로 지정한 대상입니다. 노드 id를 지정하지 않았을 때만 씁니다. 기본값은 -1(미지정)입니다.

|`registerPreMergeHook(HgHook)`
|병합이 작업 사본을 건드리기 전에, 작업 사본 잠금을 쥔 채 실행하는 훅입니다(컨텍스트 키 `repository`, `targetRev`, `targetNodeId`). false를 반환하면 병합이 중단됩니다. `null`은 무시합니다.

|`registerPostMergeHook(HgHook)`
|병합 후, dirstate를 갱신하는 중에 실행하는 훅입니다(컨텍스트 키 `conflicted`, `conflicts`, `repository`). 반환값은 무시하며 던진 예외는 경고로 로그에 남깁니다. `null`은 무시합니다.

|`getMessages()`
|`abort()`가 출력한 내용입니다(`aborting the merge, updating back to ...`).
|===

실행:

* `MergeResult call() throws IOException, HgLockException`: `MergeResult`는 `isConflicted()`(해결되지 않은 충돌 파일이 있으면 true이며 그 파일 내용에는 충돌 마커가 들어 있습니다)와 `getConflicts()`(저장소 기준 경로, 깨끗하면 빈 목록)를 가집니다. 충돌은 예외가 아니라 결과로 보고합니다. 대상이 현재 부모이거나 그 조상이면 아무것도 바뀌지 않고, 현재 부모가 대상의 조상이면 작업 사본을 대상으로 앞으로 옮기며(fast-forward), 그 밖에는 파일 단위 3-way 병합을 합니다. `HgValidationException`("Merge rejected by PRE_MERGE hook"), 빈 저장소에서 `IllegalStateException`, 노드 id도 유효한 리비전 번호도 지정하지 않았을 때 `IllegalArgumentException`, 대상이나 현재 부모가 체인지로그에 없거나 공통 조상이 없을 때 `HgRevisionNotFoundException`을 던집니다.
* `void abort() throws IOException, HgLockException`: dirstate에 두 번째 부모가 없으면 `HgValidationException("no merge in progress")`을, 저장소에 첫 번째 부모가 없으면 `IllegalStateException`을, 되돌아갈 리비전이 체인지로그에 없으면 `HgRevisionNotFoundException`을 던집니다. 작업 사본을 p1(또는 병합 상태에 기록된 로컬 쪽)으로 복원하고 부모를 하나로 되돌리며 `.hg/merge/state2`를 지웁니다.

잠금과 dirstate: `call()`은 `lockWorkingCopy()`를 잡고 revlog 캐시를 비운 뒤 병합을 `changingParents(...)`로 감쌉니다. `abort()`는 잠금 전에 dirstate와 병합 상태를 읽고, 그다음 `lockWorkingCopy()`와 `changingParents(...)`를 씁니다. `.hgsubstate`의 서브저장소 상태가 바뀌면 병합하거나 체크아웃합니다.

hg 원본과 다른 점(abort javadoc): `call()` 이후에는 dirstate의 부모 1이 이미 p1이므로, abort는 매니페스트 diff 대신 p1의 매니페스트에 맞춰 모든 경로를 다시 씁니다.

[source,java]
----
MergeCommand.MergeResult r = new MergeCommand(repo)
        .setRevision(5)
        .call();
boolean conflicts = r.isConflicted();
----

=== Summary

작업 사본의 요약 개요를 구합니다(`hg summary`). 텍스트 대신 구조화된 레코드를 반환합니다.

[cols="2,5"]
|===
|메서드 |의미

|(없음)
|생성자 `SummaryCommand(HgRepository)`만 있고 public 설정자는 없습니다.
|===

실행: `SummaryInfo call() throws IOException`. `null`을 반환하지 않습니다. `SummaryInfo`는 record이며 `parents`(없음, 하나, 병합 중에는 둘이며 각 `ParentInfo(revision, node, description)`는 로컬 리비전 번호(체인지로그가 없거나 노드를 모르면 -1), 40자 hex 노드 id, 전체 커밋 메시지(읽을 수 없으면 빈 문자열)입니다), `branch`(현재 브랜치 이름), `activeBookmark`(없으면 `null`), `modified`, `added`, `removed`, `unknown`(파일 개수), `mergeInProgress`(부모가 둘이면 true), `currentPhase`(첫 번째 부모의 `PhaseRoots.Phase`이며 알 수 없거나 부모가 없으면 public)를 가집니다.

잠금과 dirstate: 자체적으로 잠금을 잡지 않습니다. `ParentsCommand`, `BookmarkCommand.getActiveBookmark()`, `StatusCommand`를 쓰므로 Status 항목에서 설명한 status 보정 잠금 동작이 적용됩니다.

hg 원본과 다른 점: 터미널 텍스트 대신 구조화된 레코드를 반환합니다(javadoc).

[source,java]
----
SummaryCommand.SummaryInfo s = new SummaryCommand(repo).call();
String branch = s.branch();
int dirty = s.modified() + s.added() + s.removed();
----

=== Worktree

주 저장소의 저장소(store)를 공유하는 새 작업 사본을 만듭니다(`hg share`이며 javadoc은 Git의 worktree에 빗댑니다).

[cols="2,5"]
|===
|메서드 |의미

|`setNewWorktreeDir(File)`
|새 작업 사본의 디렉터리입니다. 존재하지 않거나 비어 있어야 합니다. `call()` 전에 지정해야 합니다.
|===

실행: `HgRepository call() throws IOException, HgLockException`. 디렉터리를 지정하지 않으면 `IllegalStateException`, 디렉터리가 비어 있지 않거나 디렉터리 생성, 연결, 공유 후 체크아웃에 실패하면 `IOException`을, 공유 후 체크아웃이 잠금을 얻지 못하면 `HgLockException`을 던집니다. `.hg/sharedpath`(원본 `.hg`의 정규 경로)를 쓰고 `requires`를 복사해 `shared`를 더한 뒤 새 `HgRepository`를 반환합니다.

잠금과 dirstate: 체크아웃 동안 새 작업 사본의 `lockWorkingCopy()`를 잡습니다. 저장소에 리비전이 있으면 `UpdateCommand`(`setForce(true)`, 리비전 `tip`)를 실행하며 이 명령이 다시 `lockWorkingCopy()`와 `changingParents(...)`를 씁니다. 빈 저장소이면 40바이트 부모 스텁 dirstate를 씁니다. 여기서 `changing_files`는 쓰지 않습니다.

hg 원본과 다른 점: javadoc에 따르면 tip 체크아웃은 실제 `hg share`를 따른 것이고, 빈 저장소의 스텁 dirstate는 기존 테스트 기대치를 위해 유지됩니다.

[source,java]
----
HgRepository wt = new WorktreeCommand(repo)
        .setNewWorktreeDir(new File("/work/proj-wt"))
        .call();
----

=== Unshare

공유된 저장소의 store를 복사해 와서 일반 저장소로 바꿉니다(`hg unshare`).

[cols="2,5"]
|===
|메서드 |의미

|(없음)
|생성자 `UnshareCommand(HgRepository)`만 있고 public 설정자는 없습니다.
|===

실행: `HgRepository call() throws IOException, HgLockException`. 새 저장소 객체를 반환하며 인자로 넘긴 객체는 이후 쓰면 안 됩니다. `.hg/sharedpath`가 없으면 `HgValidationException("this is not a shared repo")`을 던집니다. `sharedpath`를 `sharedpath.old`로 옮기고 `requires`에서 `shared`/`relshared`를 지우며, share-safe 저장소이면 원본 `hgrc`를 앞에 붙이고, 이어서 공유 중인 서브저장소도 unshare합니다.

잠금과 dirstate: 전체 작업 동안 공유 store 잠금(`lockStoreWithoutRecovery(timeout)`)을 쥐고, 공유를 끊는 동안 새 store의 잠금(`StoreCopy.copyStore`가 반환)을 함께 쥡니다. 작업 사본 잠금은 잡지 않고 `changing_files`/`changing_parents`도 쓰지 않습니다.

hg 원본과 다른 점: javadoc은 `cmd_impls.clone.unshare`를 따른다고 적고 있으며 어긋나는 점은 명시되어 있지 않습니다.

[source,java]
----
HgRepository normal = new UnshareCommand(sharedRepo).call();
----
