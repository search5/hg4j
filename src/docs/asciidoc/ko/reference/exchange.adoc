== Transports

다른 저장소와 통신하는 명령은 `HgRemoteConnectionFactory.createConnection(url, config)`로 연결을 엽니다. 팩토리는 등록된 `TransportProtocol` 중 주소를 처리할 수 있는 첫 번째를 고릅니다. `HgRemoteConnectionFactory.register(...)`로 추가한 사용자 프로토콜이 가장 먼저 검사됩니다.

[cols="2,5"]
|===
|주소 형식 |클라이언트 클래스와 동작

|`ssh://...`
|`HgSshClient`: Mercurial SSH 와이어 프로토콜입니다. 주소에서 `user[:pass]@host[:port]`를 해석합니다(기본 포트 22). 키 또는 비밀번호 자격 증명은 `CredentialsProvider`에서 가져옵니다(키 경로와 암호문은 `SshKeyCredentialsProvider`, 사용자와 비밀번호는 `UsernamePasswordCredentialsProvider`). SSH 와이어 프로토콜 v2는 JVM 속성 `hg4j.ssh.v2.enabled=true`를 지정하지 않으면 꺼져 있습니다.

|`file://...` 또는 존재하는 로컬 디렉터리 경로
|`HgLocalClient`: `hg` 프로세스를 실행하지 않고 자바로 다른 저장소를 직접 읽고 씁니다.

|`http://...` 또는 `https://...`
|`HgRemoteClient`: HTTP 와이어 프로토콜 v1입니다. `https://user:pass@host/path`처럼 주소에 자격 증명을 넣을 수 있습니다.

|그 외
|`HgRemoteClient`로 처리합니다.
|===

=== Authentication for HTTP(S)

* 주소에 들어 있는 자격 증명이나, 해당 설정자를 제공하는 명령의 `setCredentialsProvider(...)`로 지정한 자격 증명은 HTTP Basic 인증에 쓰입니다. Mercurial과 같이 서버가 Basic 챌린지와 함께 401로 응답한 뒤에야 전송되고, 이후 요청에는 바로 전송됩니다.
* 주소에 비밀번호가 없으면 `[auth]` 섹션을 조회합니다(`HgAuthConfig`). 항목은 `<group>.<setting> = value` 형식이며 설정은 `prefix`, `username`, `password`, `schemes`(기본 `https`)입니다. 접두어가 가장 길게 일치하는 그룹이 선택되고, 사용자를 지정한 그룹은 주소의 사용자와 일치해야 하며, 접두어 `*`는 모든 호스트와 일치합니다. `cert`와 `key`는 쓰지 않습니다.
* `[auth]` 섹션은 사용자 수준 파일(`HGRCPATH`가 있으면 그것, 없으면 `/etc/mercurial/hgrc`, `~/.hgrc`, `~/.config/hg/hgrc`)을 먼저 읽고, 그 위에 저장소 설정을 덮어씁니다.
* `createConnection(url, repository.getConfig())`를 호출하는 명령만 `[auth]`를 적용합니다. Fetch, Pull, Push, Incoming, Outgoing이 여기에 해당합니다. 아래 명령 중 `setCredentialsProvider`를 제공하는 것은 Fetch와 Pull입니다. 이 설정자가 없는 명령은 주소의 자격 증명이나 `[auth]`에 의존합니다.

아래에서 쓰는 잠금 용어입니다. `lockWorkingCopy()`는 작업 디렉터리 잠금(`wlock`), `lockStore()`는 저장소 잠금(`lock`)입니다. `changingParents(...)` 또는 `openChangingParents`는 dirstate의 `changing_parents` 컨텍스트입니다.

=== Clone

저장소를 새 디렉터리로 복제합니다. `hg clone`에 대응합니다.

[cols="2,5"]
|===
|설정자 |의미

|`setSource(String)`
|원본 주소입니다(필수).

|`setDirectory(File)`
|대상 디렉터리입니다(필수, 비어 있거나 없어야 함).

|`setStream(Boolean)`
|`hg clone --stream` / `--no-stream`입니다. `null`이면 원격의 `stream-preferred`를 따릅니다.

|`setPull(boolean)`
|`hg clone --pull`입니다. 로컬 원본이어도 항상 changeset을 pull합니다. 지정하지 않으면 로컬 원본은 저장소(store)를 복사하며, 가능하면 하드 링크를 씁니다.

|`setProgressMonitor(ProgressMonitor)`
|진행 상황 수신자입니다. `null` 인자는 무시됩니다.
|===

그 밖의 공개 메서드로 `getMessages()`가 있으며 복제가 보고한 내용(예: `streaming all changes`)을 돌려줍니다.

실행: `HgRepository call() throws IOException, HgLockException`. 새 저장소를 반환합니다. 원본이나 디렉터리가 없으면 `IllegalStateException`, 대상 디렉터리가 비어 있지 않으면 `HgValidationException`을 던집니다. pull된 저장소에 리비전이 없으면 체크아웃 없이 일찍 반환합니다.

잠금과 dirstate: `init` 직후 대상의 작업 디렉터리 잠금을 잡고 마지막 update까지 유지합니다(`destrepo.wlock()`). 로컬 원본 복사에서는 원본 저장소 잠금을 시도만 하며(`lockStore(0)`), 다른 쪽이 잡고 있으면 복사를 포기하고 changeset을 pull합니다. secret changeset이 있는 원본은 복사하지 않습니다. 복사 중에는 대상 저장소 잠금을 잡습니다. 체크아웃은 `changingParents(...)` 안에서 실행되어 dirstate 부모를 지정하고 항목을 기록합니다. `.hgsub`에 선언된 서브저장소는 이후에 체크아웃됩니다(`UpdateCommand.recursiveSubrepoCheckout`).

hg 원본과 다른 점: 원본 주소를 `.hg/hgrc`의 `[paths] default`로 기록합니다(로컬 경로는 절대 경로). javadoc은 이것이 실제 `hg clone`이 쓰는 형식이라고 설명합니다.

[source,java]
----
HgRepository repo = new CloneCommand()
    .setSource("https://example.org/repo")
    .setDirectory(new File("work"))
    .setStream(null)
    .call();
----

=== Pull

원격 저장소의 changeset을 로컬로 가져옵니다. `hg pull`에 대응합니다. 전송은 `FetchCommand`에 위임하고, 비어 있는 dirstate 부모를 가장 최근에 pull한 head로 옮깁니다.

[cols="2,5"]
|===
|설정자 |의미

|`setSource(String)`
|원본 주소 또는 `[paths]` 별칭입니다. 비어 있으면 `paths.default`를 씁니다. 둘 다 없으면 `IllegalStateException`입니다.

|`setRevisions(List<String>)`
|`hg pull -r REV`입니다. 지정한 리비전과 그 조상만 가져옵니다.

|`setStream(Boolean)`
|`--stream` / `--no-stream`입니다. `null`이면 원격의 `stream-preferred`를 따릅니다.

|`setTreeFilter(HgTreeFilter)`
|저장 대상을 제한합니다. `HgTreeFilter.ALL`이 아닐 때만 전달되므로, narrow clone 저장소 자신의 narrowspec은 그대로 적용됩니다.

|`setProgressMonitor(ProgressMonitor)`
|진행 상황 수신자입니다. `null` 인자는 무시됩니다.

|`setCredentialsProvider(CredentialsProvider)`
|연결에 쓸 자격 증명입니다.

|`setStoreFingerprints(List<String>)`
|복제가 요청하는 shape 지문(텍스트)입니다. clone bundle을 고르는 데 쓰입니다(`store_fingerprints`).

|`setShardsSets(List<Set<String>>)`
|사용 가능한 sharded clone bundle 묶음을 이루는 shard 지문(텍스트) 집합들입니다(`shards_sets`).
|===

그 밖의 공개 메서드로 `getMessages()`와, 이미 파싱된 bundle을 적용하는 `applyBundle(ChangegroupParser.ChangegroupBundle)` 및 오버로드 `(bundle, int lockTimeoutMs)`, `(bundle, int lockTimeoutMs, FetchCommand.PostLockValidator)`가 있습니다.

실행: `List<byte[]> call() throws IOException, HgLockException`. `FetchCommand.call()`의 결과 목록(`byte[]` 노드 id)을 반환합니다. `applyBundle(...)`의 반환과 예외도 같습니다.

잠금과 dirstate: `call()`은 `lockWorkingCopy()`를 잡은 뒤 `FetchCommand.call()`을 실행하며, 그 안에서 작업 디렉터리 잠금과 저장소 잠금을 다시 잡습니다(Fetch 참고). 결과가 비어 있지 않으면 `changingParents(...)`를 실행하고, dirstate의 첫 번째 부모가 전부 0이면 결과의 마지막 원소로 설정합니다. `applyBundle(...)`은 `lockWorkingCopy(lockTimeoutMs)`를 잡고(기본 시간 제한은 `repository.resolvePushLockTimeoutMs()`) 같은 `changingParents` 단계를 씁니다. 북마크 병합은 `FetchCommand` 안에서 이루어집니다(`BookmarkCommand.mergeFromRemote()`).

[source,java]
----
List<byte[]> pulled = new PullCommand(repo)
    .setSource("default")
    .setRevisions(List.of("tip"))
    .call();
----

=== Push

로컬 changeset을 원격 저장소로 보냅니다. `hg push`에 대응합니다.

[cols="2,5"]
|===
|설정자 |의미

|`setDestination(String)`
|대상 주소 또는 `[paths]` 별칭입니다. 비어 있으면 `paths.default-push`, 그다음 `paths.default`를 씁니다. 모두 없으면 `IllegalStateException`입니다.

|`setForce(boolean)`
|`hg push --force`입니다. "새 원격 head 생성" 검사를 건너뜁니다.

|`setAllowNewBranch(boolean)`
|`hg push --new-branch`입니다. 원격에 없는 이름 있는 브랜치를 보낼 수 있게 합니다. 지정하지 않으면 "push creates new remote branches"로 중단됩니다.

|`setBookmarks(String...)`
|`hg push -B NAME ...`입니다. 지정한 북마크를 원격에 만들거나 옮기거나(로컬에 없으면) 삭제하며, 해당 북마크의 조상만 전송합니다.

|`registerPrePushHook(HgHook)`
|push 전에 실행되는 훅입니다. false를 반환하면 push는 `HgValidationException`으로 실패합니다.

|`registerPostPushHook(HgHook)`
|push 후에 실행되는 훅입니다.

|`setProgressMonitor(ProgressMonitor)`
|LFS 업로드 진행 상황과 Mercurial이 출력하는 관련 줄을 받습니다.
|===

그 밖의 공개 메서드로 `getBookmarkResult()`(0 정상, 1 북마크 갱신 실패, 2 북마크 거부)와 `getMessages()`(예: `cannot lock source repo, skipping local public phase update`)가 있습니다.

실행: `String call() throws IOException, HgLockException`. 상태 문자열을 반환합니다. 로컬 저장소가 비어 있으면 `No changesets to push (empty local repository)`를 반환합니다. 그 밖의 결과 문자열은 javadoc에 명시되어 있지 않아 여기에 적지 않았습니다. 실패 시 `HgValidationException`이 던져지며 메시지 예는 `abort: repository is unrelated`, `abort: push creates new remote branches: ...`, `abort: push creates new remote head ...`, LFS 요구 사항 메시지 `required features are not supported in the destination: lfs`입니다.

잠금과 dirstate: 먼저 연결을 열고 `lockSourceRepository()`를 실행합니다. 이 메서드는 `lockStore(resolvePushLockTimeoutMs())`를 잡으며, `experimental.bundle2.pushback`이 true일 때만 그보다 먼저 `lockWorkingCopy(...)`를 잡습니다. 잠금은 changeset, phase, 북마크 전송이 끝날 때까지 유지됩니다. 원본 저장소를 잠글 수 없으면 push는 계속되고 로컬 public phase 갱신만 건너뜁니다(메시지가 추가됨). 중단된 트랜잭션이 있으면 그래도 중단됩니다. `changingParents` 사용은 확인되지 않았습니다.

hg 원본과 다른 점: `setCredentialsProvider`가 없습니다. 주소의 자격 증명과 `[auth]`가 적용됩니다.

[source,java]
----
PushCommand push = new PushCommand(repo)
    .setDestination("default")
    .setAllowNewBranch(true);
String result = push.call();
----

=== Fetch

changeset을 저장소로 내려받는 저수준 네트워크 동기화 명령입니다. javadoc에 따르면 revlog 저장소, 북마크, phase를 원자적으로 갱신하지만 작업 디렉터리 dirstate는 수정하지 않습니다. `PullCommand`가 이 위에 만들어져 있습니다.

[cols="2,5"]
|===
|설정자 |의미

|`setSource(String)`
|원본 주소입니다(필수, 없으면 `IllegalStateException`). 여기서는 `[paths]` 해석을 하지 않습니다.

|`setRevisions(List<String>)`
|지정한 리비전과 그 조상만 가져옵니다. 각각 원격에서 조회하므로 노드 접두어, 북마크, 태그, 브랜치 이름을 쓸 수 있으며 원격이 `lookup`을 지원해야 합니다.

|`setStream(Boolean)`
|`--stream` / `--no-stream`입니다. `null`이면 `stream-preferred`를 따릅니다.

|`setTreeFilter(HgTreeFilter)`
|경로 필터입니다. `ALL`로 두면 저장소 자신의 narrowspec을 읽어 옵니다.

|`setProgressMonitor(ProgressMonitor)`
|진행 상황 수신자입니다. `null` 인자는 무시됩니다.

|`setCredentialsProvider(CredentialsProvider)`
|연결에 쓸 자격 증명입니다.

|`setWorkingCopyLock(boolean)`
|`applyBundle`이 작업 디렉터리 잠금도 잡을지 정합니다. 기본값은 `true`(pull)이고, unbundle에서는 `false`입니다.

|`setStoreFingerprints(List<String>)`
|shape 복제용 shape 지문입니다.

|`setShardsSets(List<Set<String>>)`
|sharded clone bundle용 shard 지문 집합입니다.
|===

그 밖의 공개 메서드로 `getMessages()`, `applyBundle(bundle)`, `applyBundle(bundle, int lockTimeoutMs)`, `applyBundle(bundle, int lockTimeoutMs, PostLockValidator)`가 있고, 함수형 인터페이스 `PostLockValidator`의 `validate()`는 잠금을 잡은 뒤 아무것도 적용하기 전에 실행됩니다(push 경합 재검증용).

실행: `List<byte[]> call() throws IOException, HgLockException`. `applyBundle(...)`은 가져온 커밋을 `List<byte[]>`로 반환하며, 빈 bundle이면 빈 목록을 반환합니다.

잠금과 dirstate: `call()`은 저장소 상태를 읽기 전에 `lockWorkingCopy()`와 `lockStore()`를 차례로 잡습니다. `applyBundle(...)`은 `lockWorkingCopy(lockTimeoutMs)`(`setWorkingCopyLock(false)`이면 아무 일도 하지 않는 잠금)를 잡은 뒤 `lockStore(lockTimeoutMs)`를 잡습니다. 잠금을 잡은 뒤 dirstate와 fncache를 백업하고, 적용이 실패하면 잠금을 쥔 채로 롤백합니다. 이 클래스에서 `changingParents` 사용은 확인되지 않았습니다.

[source,java]
----
List<byte[]> nodes = new FetchCommand(repo)
    .setSource("ssh://hg@example.org/repo")
    .setRevisions(List.of("default"))
    .call();
----

=== Incoming

원격에는 있고 로컬에는 없는 changeset을 나열합니다. `hg incoming`에 대응합니다(출력은 `changeset:`, `user:`, `summary:` 줄 형태입니다).

[cols="2,5"]
|===
|설정자 |의미

|`setSource(String)`
|원본 주소입니다(필수). `[paths]` 별칭이나 기본값 해석은 없으며, 지정하지 않으면 `IllegalArgumentException`입니다.
|===

실행: `List<String> call() throws IOException`. 반환값은 incoming changeset마다 세 줄(`changeset:   <12자리 hex>`, `user:        ...`, `summary:     ...`)이거나 한 줄 `no incoming changes found`입니다. 첫 연결이 실패하면 `IOException("Remote connection failed for ...")`을 던집니다. changegroup 세부 정보를 가져오지 못하면 예외 대신 누락된 head id와 실패 문구로 대체한 결과를 반환합니다.

잠금과 dirstate: 잠금을 잡지 않고 `changingParents`도 쓰지 않습니다.

[source,java]
----
List<String> lines = new IncomingCommand(repo)
    .setSource("https://example.org/repo")
    .call();
----

=== Outgoing

원격에 없는 로컬 changeset을 나열합니다. `hg outgoing`에 대응합니다.

[cols="2,5"]
|===
|설정자 |의미

|`setDestination(String)`
|대상 주소입니다(필수, 지정하지 않으면 `IllegalArgumentException`). 별칭이나 기본값 해석은 없습니다.
|===

실행: `List<String> call() throws IOException`. 원격 head가 포함하지 않는 changeset마다 `changeset:   <rev>:<12자리 hex>`, `user:        ...`, `summary:     ...` 줄을 반환하며, 없으면 `no outgoing changes found`를 반환합니다. 연결 실패는 `IOException("Remote connection failed for ...")`입니다.

잠금과 dirstate: 잠금을 잡지 않고 `changingParents`도 쓰지 않습니다.

[source,java]
----
List<String> lines = new OutgoingCommand(repo)
    .setDestination("default-push-url")
    .call();
----

=== Bundle

changeset을 로컬 bundle 파일로 씁니다. `hg bundle`에 대응합니다.

[cols="2,5"]
|===
|설정자 |의미

|`setOutputFile(File)`
|쓸 bundle 파일입니다(필수).

|`setBaseRevision(String)`
|`hg bundle --base REV`입니다. 이 리비전과 조상은 제외됩니다. `"null"`(대소문자 무시), `""`, `"-1"`이면 전부 묶습니다(`-a`). 필수이며, 지정하지 않으면 `IllegalStateException`입니다. 대상 주소 추론이 구현되어 있지 않기 때문입니다.

|`setRevision(String)`
|`hg bundle -r REV`입니다. 이 리비전과 조상으로 제한합니다. 지정하지 않으면 모든 리비전입니다.

|`setType(BundleType)` / `setType(String)`
|`--type`입니다. 값은 `none-v1`(기본), `gzip-v1`, `bzip2-v1`, `none-v3`, `gzip-v3`, `bzip2-v3`입니다. 문자열 형태는 대소문자를 구분하지 않으며 모르는 이름은 `IllegalArgumentException`입니다.
|===

실행: `int call() throws IOException, HgLockException`. 기록한 changeset 수를 반환합니다. 선택된 집합이 비어 있거나 저장소가 비어 있으면 파일을 쓰지 않고 `0`을 반환합니다. 리비전을 찾지 못하면 `IOException`입니다. treemanifest 또는 LFS 저장소에 `-v1` 형식을 지정하면 `IllegalStateException("abort: repository does not support bundle version 01 ...")`을 던집니다.

잠금과 dirstate: 잠금을 잡지 않으며(소스 주석: "like real hg, `bundle` only reads: no lock"), `changingParents`도 쓰지 않습니다.

hg 원본과 다른 점(javadoc 기준): `paths.default-push`나 `paths.default`에서 암묵적 대상을 추론하지 않으므로 base가 항상 필요합니다. `-v3` 계열은 cg3 changegroup을 담은 `HG20` bundle2 봉투를 만듭니다. sidedata(cg5)는 의도적으로 협상하지 않으며, javadoc은 이것이 실제 `hg bundle`의 한계이기도 하다고 설명합니다. bundle에 포함된 LFS 리비전의 blob은 기본 경로 또는 `[lfs] url`의 LFS 저장소로 먼저 업로드됩니다.

[source,java]
----
int n = new BundleCommand(repo)
    .setOutputFile(new File("all.hg"))
    .setBaseRevision("null")
    .setType("gzip-v1")
    .call();
----

=== Unbundle

로컬 bundle 파일을 저장소에 적용합니다. `hg unbundle`에 대응합니다. `HG10UN`, `HG10GZ`, `HG10BZ`, `HG20`(bundle2) 파일을 읽습니다.

[cols="2,5"]
|===
|설정자 |의미

|`setBundleFile(File)`
|적용할 bundle 파일입니다(필수, 존재해야 하며 아니면 `IllegalStateException`).
|===

실행: `List<byte[]> call() throws IOException, HgLockException`. `FetchCommand.applyBundle`이 가져온 커밋을 반환합니다. 알 수 없는 헤더나 지원하지 않는 bundle1 압축 형식은 `HgCorruptDataException`을 던집니다.

잠금과 dirstate: `FetchCommand.setWorkingCopyLock(false)`를 호출합니다(소스 주석: "real hg: `unbundle` holds only the store lock"). 따라서 `lockStore(...)`만 잡고 dirstate는 건드리지 않습니다. `changingParents`는 쓰지 않습니다.

[source,java]
----
List<byte[]> imported = new UnbundleCommand(repo)
    .setBundleFile(new File("all.hg"))
    .call();
----

=== Archive

리비전의 버전 관리 정보 없는 스냅샷을 추출합니다. `hg archive`에 대응합니다.

[cols="2,5"]
|===
|설정자 |의미

|`setDestination(File)`
|출력 디렉터리 또는 아카이브 파일입니다(필수, 없으면 `IllegalArgumentException`).

|`setRevision(String)`
|아카이브할 리비전입니다. 기본값은 `tip`이며 찾지 못하면 `IOException`입니다.

|`setType(String)`
|`files`, `zip`, `uzip`, `tar`, `tgz`, `tbz2` 중 하나입니다. 지정하지 않으면 대상 확장자로 판별합니다(`.tbz2`/`.tar.bz2`, `.tgz`/`.tar.gz`, `.tar`, `.zip`, 그 외는 `files`). 모르는 이름은 `IllegalArgumentException`입니다.

|`setPrefix(String)`
|zip과 tar 아카이브의 모든 항목에 붙는 디렉터리 접두어입니다. `files`에서는 무시됩니다. 기본값은 대상 파일명에서 형식별 접미사를 뺀 이름입니다.

|`setInclude(String...)`
|`hg archive -I`입니다. 이 패턴(기본은 glob)과 일치하는 파일만 포함합니다.

|`setExclude(String...)`
|`hg archive -X`입니다. 이 패턴과 일치하는 파일을 제외합니다.

|`setCwd(String)`
|저장소 루트 기준의 현재 디렉터리이며, 상대 패턴을 해석하는 기준입니다.
|===

실행: `void call() throws IOException`. include/exclude 패턴과 일치하는 파일이 없으면 `HgValidationException("no files match the archive pattern")`을 던집니다.

잠금과 dirstate: 잠금을 잡지 않고 `changingParents`도 쓰지 않습니다.

hg 원본과 다른 점(javadoc 기준): `txz`(lzma)는 의도적으로 구현하지 않았습니다. `.hg_archival.txt` 항목을 쓰고, zip과 tar 항목에 디렉터리 접두어를 붙이며, 실행 비트와 심볼릭 링크를 유지하고, tree manifest는 `HgRepository.getManifestAtCommit`로 읽습니다.

[source,java]
----
new ArchiveCommand(repo)
    .setRevision("tip")
    .setDestination(new File("snapshot.tar.gz"))
    .call();
----

=== Clonebundles

URL의 clone bundle을 내려받아 적용합니다. Mercurial clone bundles 기능의 클라이언트 쪽입니다. private 생성자를 가진 final 클래스이고 정적 메서드가 두 개이므로 설정자는 없습니다.

[cols="2,5"]
|===
|메서드 |의미

|`downloadAndApply(HgRepository, String url)`
|`url`의 bundle을 일반 HTTP(S) GET(와이어 프로토콜 프레이밍 없음, 연결 10초, 읽기 60초 시간 제한)으로 내려받아 `UnbundleCommand`로 적용합니다.

|`applyEntries(HgRepository, HgRemoteConnection peer, List<ClonebundleSelection.Entry> entries, List<String> messages)`
|`best_clonebundles`가 고른 bundle들을 적용합니다. 각각 HTTP로, 또는 `peer-bundle-cache://` 항목이면 `peer`를 통해 서버 캐시에서 가져오고, `DIGEST`(sha256 우선, 그다음 sha512)를 검사한 뒤 스트림(`stream2` 파트) 또는 changegroup bundle로 적용합니다. 진행 줄은 `messages`에 추가됩니다.
|===

반환과 예외: 둘 다 `List<byte[]>`를 반환하며(changegroup bundle이 가져온 커밋, 스트림 bundle만 적용했으면 빈 목록) `IOException, HgLockException`을 던집니다. HTTP 200이 아니면 `HgProtocolException`입니다. 가져오기 오류나 digest 불일치는 `HgValidationException`이 되며, `applyEntries`는 `error applying bundle`과 함께 `ui.clonebundles=false` 안내를 포함합니다.

잠금과 dirstate: 두 메서드 모두 다운로드와 적용 내내 `lockStore()`를 유지합니다. 작업 디렉터리 잠금과 `changingParents`는 이 클래스에서 쓰지 않습니다(내부의 `UnbundleCommand`가 `FetchCommand.applyBundle`을 통해 저장소 잠금을 다시 잡습니다).

hg 원본과 다른 점: 다운로드가 실패해도 일반 pull로 대체하지 않으며 모든 실패가 예외로 전파됩니다. 마지막 증분 pull은 호출자가 직접 해야 합니다.

[source,java]
----
List<byte[]> imported = ClonebundlesCommand
    .downloadAndApply(repo, "https://cdn.example.org/bundle.hg");
----

=== NarrowClone

include와 exclude 패턴 또는 store shape로 저장소의 일부만 복제합니다. narrow 확장의 `hg clone`(`--include`, `--exclude`)과 `--shape`에 대응합니다.

[cols="2,5"]
|===
|설정자 |의미

|`NarrowCloneCommand()`
|생성자는 저장소를 받지 않습니다. 대상은 `call()`이 만듭니다.

|`setSource(String)`
|원본 주소입니다(필수).

|`setDirectory(File)`
|대상 디렉터리입니다(필수).

|`addIncludePath(String)`
|include 패턴을 추가합니다. `null`은 무시됩니다. 패턴은 `narrowspec.normalizepattern()`처럼 정규화됩니다. 기본 종류는 `path:`이고, 끝의 `/`는 제거되며, `.`, `..`, 빈 구성 요소는 거부됩니다.

|`addExcludePath(String)`
|exclude 패턴을 추가합니다. 규칙은 같습니다. exclude만 주어지면 `path:.`를 include합니다.

|`setShape(String)`
|`hg clone --shape NAMES`입니다. `exp-shape-1`을 알리는 서버의 store shape 이름을 쉼표로 구분해 지정합니다. shape의 패턴이 narrowspec이 되고 이름은 `store-shape`에 보관됩니다.
|===

그 밖의 공개 메서드로 `getMessages()`가 있습니다.

실행: `Hg call() throws IOException, HgLockException`. 새 저장소의 `Hg` 파사드를 반환합니다. 원본이나 디렉터리가 없으면 `IllegalStateException`이고, `exp-shape-1`이 없는 원격에 `--shape`를 쓰면 `HgValidationException`입니다. shape는 아무것도 만들기 전에 먼저 요청하므로 거부되어도 저장소가 남지 않습니다.

잠금과 dirstate: `init` 이후 끝까지 새 저장소의 `lockWorkingCopy()`를 유지합니다. 그 안에서 `.hg/requires`에 `narrowhg-experimental`을 추가하고, 짧은 `lockStore()` 범위에서 `.hg/store/narrowspec`을 쓰며, `.hg/narrowspec.dirstate`도 씁니다. shape를 쓸 때는 `store-shape`도 `lockStore()` 아래에서 기록합니다. 이후 narrow 필터로 `PullCommand`를 실행하고 revlog 캐시를 비운 뒤 같은 필터로 `UpdateCommand`를 실행합니다. 이 클래스에서 `changingParents`를 직접 호출하지는 않습니다.

[source,java]
----
Hg hg = new NarrowCloneCommand()
    .setSource("https://example.org/repo")
    .setDirectory(new File("narrow"))
    .addIncludePath("src")
    .addExcludePath("src/gen")
    .call();
----

=== ShardedStreamBundles

저장소의 shard마다 스트리밍 bundle을 하나씩 씁니다. `hg debug::sharded-stream-bundles`에 대응합니다. bundle은 `server.peer-bundle-cache-root`(`.hg` 기준 상대 경로, 기본 `bundle-cache`)에 `hg-sharded-<group>-<shard fingerprint>.hg`로 기록됩니다. final 클래스입니다.

[cols="2,5"]
|===
|설정자 |의미

|`setGroupId(String)`
|그룹 id(16진수 8자리)입니다. 지정하지 않으면 새 난수를 쓰며, 한 번 실행에서 만든 bundle은 같은 id를 공유합니다.
|===

실행: `List<File> call() throws IOException, HgLockException`. 기록한 파일을 shard 이름 순서대로 반환합니다. `experimental.server.stream-narrow-clones`가 `true` 또는 `1`이 아니면 `HgValidationException("server does not support narrow stream clones")`을 던집니다.

잠금과 dirstate: `lockWorkingCopy()`와 `lockStore()`를 차례로 잡고 실행 내내 둘 다 유지하므로, 모든 shard가 저장소의 같은 상태에서 동시에 만들어집니다. `changingParents`는 쓰지 않습니다.

[source,java]
----
List<File> files = new ShardedStreamBundlesCommand(repo)
    .setGroupId("0a1b2c3d")
    .call();
----

=== Paths

저장소 설정의 `[paths]` 별칭을 나열합니다. `hg paths`에 대응합니다.

설정자: 없습니다.

실행: `Map<String, String> call()`. 별칭 이름순으로 정렬된 별칭과 URL의 맵을 반환하며, `[paths]` 섹션이 없으면 빈 맵입니다(`null`이 아님). 검사 예외는 선언하지 않습니다.

잠금과 dirstate: 없습니다.

hg 원본과 다른 점(javadoc 기준): `default:pushurl` 같은 경로별 하위 옵션은 범위 밖이며, 기본 `name = url` 항목만 노출합니다.

[source,java]
----
Map<String, String> paths = new PathsCommand(repo).call();
String url = paths.get("default");
----

=== LfsUpload

지정한 리비전이 도입한 LFS blob을 업로드합니다. `hg debuglfsupload -r REV`에 대응합니다. 대상은 기본 경로 또는 `[lfs] url`의 LFS 저장소이며, push나 bundle이 하는 업로드와 같습니다.

[cols="2,5"]
|===
|메서드 |의미

|`addRevision(String)`
|blob을 업로드할 리비전을 추가합니다. 하나도 추가하지 않으면 dirstate의 첫 번째 부모를 씁니다.
|===

실행: `int call() throws IOException`. 검토한 고유 blob 수를 반환합니다(서버가 이미 가진 것은 건너뜁니다). 리비전을 찾지 못하면 `IOException("Revision not found: ...")`입니다.

잠금과 dirstate: 잠금을 잡지 않습니다. 리비전을 주지 않았을 때 dirstate 부모를 읽기만 하며 `changingParents`는 쓰지 않습니다.

[source,java]
----
int blobs = new LfsUploadCommand(repo)
    .addRevision("tip")
    .call();
----
