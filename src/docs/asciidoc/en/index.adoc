== 1. Introduction
`hg4j` is an enterprise-grade, pure Java implementation of the **Mercurial (hg) SCM** version control system. Inspired by the clean, modular decoupled architecture of **JGit** in the Git ecosystem, `hg4j` enables complete read/write capability, transactional crash durability, and seamless binary-level interoperability with the official Mercurial CLI (v7.2.2).

This reference manual describes the core architectural layout of the library, the storage format parsing, porcelain facades, and interop testing.

== 2. Core Architecture
The design of `hg4j` strictly isolates low-level storage engines (**Plumbing API**) from high-level developer convenience interfaces (**Porcelain API**).

=== 2.1 Plumbing API (Internal Plumbing)
* **`HgRepository`**: The central coordinator that governs the physical storage layout under the `.hg/` directory, handles write locks, and orchestrates transaction recovery.
* **`Dirstate`**: Handles working copy file tracking. The engine supports standard v1 format and high-throughput v2 layout (`DirstateV2Node`) designed with zero-copy binary mappings.
* **`Revlog` (v1)**: Parses index (`.i`) and data (`.d`) files, reconstructing file history chains natively in memory.
* **`TreeWalk` & `RevWalk`**: Provides high-performance iterative traversals of both file trees (manifests) and revision commit graphs.

=== 2.2 Porcelain API (User Facades)
All user-facing workflows are exposed via the `Hg` class facade.

[source,java]
----
// Initialize a repository
HgRepository repo = Hg.init().setDirectory(new File("/path/to/repo")).call();

// Add files
Hg.add(repo).addFile(new File(repo.getDirectory(), "README.md")).call();

// Commit changes
Hg.commit(repo).setMessage("Initial commit!").call();
----

== 3. Interoperability & Durability
`hg4j` is meticulously certified against official Mercurial SCM:

* **Crash Durability**: An active transaction engine tracks changes in `journal` logs and backups, allowing automatic, safe, atomic rollbacks if an error occurs.
* **OS-Level Locks**: Uses Java `FileLock` (`.hg/wlock` and `.hg/store/lock`) to ensure safety under concurrent multi-process environments.
* **Storage Optimization**: Implements line-level Myers-diff and Longest Common Subsequence (LCS) algorithms for multi-hunk delta generation, saving extensive storage overheads.
